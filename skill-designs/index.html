Skill designs

Nine Claude Code skills, and how each one works inside: the problem it solves, when it is worth running, and its run drawn as a diagram with numbered arrows.

Pick by the problem you have

Each card names the pain first. Open one to see the steps, who does what, and when the skill is too much.

meta-thinking

Large tasks go wrong halfway through. One fresh agent thinks the task through before any work starts and asks you at most three questions.

grill-me-v2

A vague task gets built on guesses. One question per message, each with options and a recommendation; facts are looked up, not asked.

create-ticket-v3

Writing tickets takes longer than the work. Short notes become a story, bug, task or epic, or a batch of them; you see every field before anything is created.

decompose-and-delegate

Your session fills up reading files. A big question about the code is split into small ones, one agent each; only their answers come back.

settle

A draft has open questions only you can answer. One point per message, each with options, pros, cons and a recommendation; your answers are applied at the end.

debate-loop

One review pass misses things. Reviewers with different focus, a separate fixer and a fresh checker, round after round, until the text does what you asked for or the round limit is reached.

test-driven-development

Tests pass while the code is wrong. Each new test is watched failing for the right reason before the smallest fix makes the suite green.

delegate-task

A long, decided task blocks your session. One background agent runs it on its own branch; its report is checked against git before it counts.

pr-review-with-auto-fix

AI review comments are hard to trust. Every finding is checked at its line, every file has a reviewer who must say whether it read it, and fixes are proven by running the tests.

How they fit together

One way to combine them, not a rule. Each also works alone.

  1. 1

    Think the task through

    meta-thinking

    Pick the route and settle the decisions that are yours.

  2. 2

    Pin down the requirements

    grill-me-v2

    One question at a time; facts are looked up.

  3. 3

    Write the ticket

    create-ticket-v3

    From your notes; you see every field before it is created.

  4. 4

    Learn how the code works today

    decompose-and-delegate

    Answers with file:line, no changes.

  5. 5

    Settle the open points of your draft plan

    settle

    One point at a time, with you.

  6. 6

    Review the plan or draft

    debate-loop

    Rounds of reviewers, within a round limit, until the plan meets your ask.

  7. 7

    Build each change test first

    test-driven-development

    A test that fails for the right reason, then the smallest fix.

  8. 8

    Run the build in the background

    delegate-task

    One agent builds and commits on its own branch; the result is checked against git.

  9. 9

    Review the pull request

    pr-review-with-auto-fix

    Narrow reviewers, checked findings, fixes proven by the tests. You decide the merge.
